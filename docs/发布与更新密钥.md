## 2. 自动更新为什么需要 HTTPS 直链

程序只信任**编译进 EXE 的公钥**，清单本身走 HTTPS 直链下载（只允许 HTTPS，回环地址才放行 http）。
所以不需要服务器后台，也不需要“正式发布到应用商店”，只要有任何一个 HTTPS 直链能放两个文件：

1. `TranslationApp.exe`（新版本体）
2. `latest.json`（RSA-PSS 签名清单）

GitHub Release 天然满足（`*.githubusercontent.com` 直链）：

- 版本本体：`https://github.com/540544841-svg/TranslationApp/releases/download/v0.3.1/TranslationApp.exe`
- 清单：`https://github.com/540544841-svg/TranslationApp/releases/latest/download/latest.json`

把**清单地址**填进「设置 → 更新与数据 → 更新清单地址」即开启自动检查更新。

## 3. 发布一版的完整流程

```powershell
# 0) 先把版本号改到 src\TranslationApp.App\TranslationApp.App.csproj 的 <Version>
#    并确认 UpdateTrust.ReleaseKeyId 与下面 -KeyId 一致

# 1) 自包含单文件发布（带 200MB 体积门禁）
pwsh -File build\publish.ps1
#    → publish\TranslationApp.exe

# 2) 生成签名更新清单（默认会校验私钥与 EXE 内置公钥是否配对）
pwsh -File build\make-update-manifest.ps1 `
  -ExePath publish\TranslationApp.exe `
  -PrivateKeyPath build\secrets\translationapp-release-private.pem `
  -Version 0.3.1 `
  -DownloadUrl "https://github.com/540544841-svg/TranslationApp/releases/download/v0.3.1/TranslationApp.exe" `
  -Notes "本次发布说明" `
  -OutputPath publish\latest.json
#    → publish\latest.json

# 3) 上传到 GitHub Release（tag 必须与 -Version 对应，例如 v0.3.1）
#    两个附件都要传：TranslationApp.exe + latest.json
gh release create v0.3.1 publish\TranslationApp.exe publish\latest.json --title "速译 0.3.1" --notes "本次发布说明"
#    没有 gh 时：在仓库 Releases 页面手动新建 tag 并上传这两个文件
```

发布后的自检（可选但推荐）：

```powershell
# 隔离进程可用性（握手 + 真实推理）
pwsh -File build\verify-ocr-worker.ps1 -Exe publish\TranslationApp.exe -Recognize

# 清单签名是否能被程序内置公钥验证通过
$e = Get-Content publish\latest.json -Raw | ConvertFrom-Json
# 打开「设置 → 诊断 → 开始诊断」即可看到「更新通道与清单验签」一行
```

## 4. 客户端更新通道怎么填

| 字段 | 值 |
| --- | --- |
| 更新清单地址 | `https://github.com/540544841-svg/TranslationApp/releases/latest/download/latest.json` |

注意：

- `latest` 只指向**最新正式发布**（预发布 / Pre-release 不会被 `latest` 命中），所以自动更新通道要用正式发布。
- 仓库必须是 Public，或者客户端能带着凭据访问；私有仓库的 Release 直链对外 404。
- 自动更新只替换 EXE；`publish\data`（便携模式数据目录）不会被触碰，所以设置与历史不受影响。

## 5. 轮换密钥

```powershell
pwsh -File build\new-update-signing-key.ps1 -PrivateKeyPath build\secrets\translationapp-release-private.pem
# 把打印出来的公钥替换到 UpdateTrust.cs 的 ReleasePublicKeyPem
# 同时提升 UpdateTrust.ReleaseKeyId（例如 release-2026-03）与 make-update-manifest.ps1 的 -KeyId 默认值
# 重新发布一次「普通更新」，让旧版本先把新公钥带过去，之后才能用新私钥签发清单
```

`make-update-manifest.ps1` 默认会校验「私钥 ↔ 程序内置公钥」配对（剔除空白字符后比对），
不配对会直接报错；只有本地联调才用 `-SkipTrustKeyCheck` 跳过。

## 6. 关于 Authenticode（为什么不签名也能跑）

- **更新清单签名**（RSA-PSS）是速译自己的信任链，已完整落地，是自动更新的安全边界。
- **Authenticode** 是 Windows 的发布者证书（消除 SmartScreen 警告），需要每年付费的代码签名证书。
  没有它时 `make-update-manifest.ps1` 会提示 `NotSigned`，需要显式加 `-AllowUnsigned`。

所以「不买证书」完全可以做自动更新；买了证书之后，只需去掉 `-AllowUnsigned`，
脚本会自动额外校验 Authenticode，并把它作为发布门禁。
