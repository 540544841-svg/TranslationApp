# TranslationApp（速译）

Windows 桌面划词 / 输入翻译工具：常驻系统托盘，全局热键呼出鼠标处翻译小窗。
技术栈：C# / WPF / .NET 10（详见 `docs/需求文档-TranslationApp-v1.0.md`）。

## 环境

- .NET SDK 10（`winget install Microsoft.DotNet.SDK.10`）
- Windows 10 1809+ / Windows 11 x64，无需管理员权限


### 让 Google 引擎可用（需要代理，且只开代理还不够）

默认引擎是 Bing（国内可直连）。若要用 Google：

1. **设置 → 高级 配置代理**：填代理地址与端口（Clash 常见 `127.0.0.1:7897`），协议可选
   **HTTP 或 SOCKS5**；作用范围保持「仅国外引擎」，这样 Bing 仍走直连不绕路。
2. **Google 的 `client=gtx` 参数会被限流**：实测同一出口 IP 上 `client=gtx` 稳定返回 HTTP 429，
   而 `client=dict-chrome-ex` 正常返回 200。程序已内置**多 client 依次尝试**
   （`dict-chrome-ex` → `gtx`），并把 429/403 归类为「配额用尽」而非笼统的「引擎异常」。

配置后用设置页的「测试代理连通性」验证——它直接探测 Google 翻译端点，按 200 / 429 / 403
给出可操作提示。**代理未开启时 Google 会翻译失败，此时请把引擎切回 Bing**
（设置 → 翻译 → 当前引擎），Bing 不需要代理。

实测（代理 `127.0.0.1:7897`、引擎 Google）：连续三次翻译成功，单次 115~145ms。

### 官方引擎的 Key 与网络可达性
- 四家官方引擎（腾讯云 TMT / 百度 / Azure Translator / DeepL）的密钥在**设置 → 引擎**页填入，
  经 Windows DPAPI（CurrentUser）加密后写入 `settings.json`（`*Encrypted` 字段，配置文件中无明文）；
  非密钥标识（SecretId / APPID / Region）按文档明文存储，便于排障。
- 每张卡片有「测试连接」（发一次 `hello` 的真实翻译请求，约消耗 5 个字符额度）：
  成功显示译文与耗时，失败按「Key 无效 / 额度用尽 / 网络不可达 / 引擎异常」分类给文案。
- **端点可达性实测（2026-09-13，本机直连、无代理、无 Key）**：

  | 端点 | 结果 | 结论 |
  |---|---|---|
  | `api.cognitive.microsofttranslator.com` | HTTP 401（`error.code` 401001） | 可达 |
  | `api-free.deepl.com` | HTTP 403（Missing Authorization header） | 可达 |
  | `api.deepl.com` | HTTP 403 | 可达 |

  即当前网络**无需代理**即可直连 Azure 与 DeepL。若在其它网络下不可达，设置页会给出
  「端点 xxx 当前不可达」提示；此时请到**设置 → 高级 → 网络代理**把作用范围设为
  **「仅国外引擎（Google / Azure / DeepL / AI）」**并填入代理（Azure / DeepL 归入该作用域）。
  重跑实测：`powershell -ExecutionPolicy Bypass -File build\probe-engines.ps1`。
- Azure / DeepL 在**没有 Key 时也能探测**（401/403 即视为可达），因此设置页打开后会后台探测一次，
  不可达时在对应卡片显示黄色提示条。

## 使用方式

| 操作 | 说明 |
|---|---|
| `Alt+D` | 在鼠标处呼出翻译小窗（输入翻译）；再按一次或 Esc 收起 |
| `Alt+S` | 划词翻译：自动取当前选中文本并翻译（阶段 2 实现，见「当前状态」） |
| `Alt+O` | 截图翻译：框选后默认**把选区图片钉在屏幕上原位显示译文**（阶段 5，见下） |
| `Ctrl+Enter` | 小窗内交换源/目标语言 |
| 托盘双击 | 打开设置 |
| 托盘右键 | 输入翻译 / 划词翻译 / 截图翻译 / 设置 / 退出（存在钉图时多一项「关闭所有钉图」） |
| 复制文本 | 开启「剪贴板监听」后自动弹出翻译（设置 → 高级，默认关闭） |
| 译文行按钮 | 收藏到生词本 / 朗读译文 / 复制译文；输入框右上角可朗读原文 |

小窗失去焦点会自动隐藏（200ms 延时），隐藏时会把键盘焦点交还给你原来的应用；
点「图钉」可按需求固定常显。热键、目标语言、引擎均可在设置中修改，改动即时生效。

### 钉图窗口（阶段 5，FR-027）

框选后图片会**钉在屏幕上原选区的位置**（`zoom = 1.0` 时逐像素还原），原文字位置上直接显示译文。
钉图四周有**扩散阴影外框**（圆角卡片），工具条在**截图下方的常驻条带**里（不遮挡图片文字）。
钉图窗口是常驻的独立窗口（不进 Alt+Tab、初始不激活、不打断你的编辑），**它自己永不自动隐藏**，
只能由你关闭。快捷键只在钉图窗口处于激活状态时生效（先单击图片即可）：

| 操作 | 说明 |
|---|---|
| 拖动图片 | 移动钉图（不写回任何设置） |
| 滚轮 | 以鼠标位置为锚点等比缩放（默认每格 ×1.1，可在设置里改） |
| `Shift+滚轮` | 精细缩放（按缩放步进的 20% 折算） |
| `Ctrl+滚轮` | 单张钉图的透明度（步进 0.1，范围 30%~100%，不写回设置） |
| 单击图片 / `空格` / `T` / 双击 | 在原文与译文之间切换 |
| `Ctrl+C` / `Ctrl+0` / `Ctrl+=` / `Ctrl+-` | 复制译文 / 回到 100% / 放大 / 缩小 |
| `Ctrl+R` | 重新翻译（翻译失败时可用） |
| `Ctrl+F` | 强制翻译（「识别语言与目标语言相同」被跳过时，工具条出现「翻译」按钮，把源语言置回自动检测重新翻译） |
| `Ctrl+Enter` | 把识别文本带回翻译小窗（可编辑、可再翻译、可入库） |
| `Esc` | 关闭这张钉图；托盘「关闭所有钉图」一次清空 |
| 右键菜单 | 放大 / 缩小 / 原始大小 / 切换原文译文 / 复制译文 / 在小窗中打开 / 重试翻译 / 强制翻译 / 恢复不透明 / 关闭（不可用的项会禁用并写明原因） |

钉图条数上限 5 张、单张 4 MP（超出自动等比缩小并提示）、总量 12 MP（超出拒绝并提示）；
达到上限**不会**静默关闭你已有的钉图。

### 划词翻译（Alt+S）使用要点

- 用法：先在任意应用中**选中文字**，再按 `Alt+S`。
- 程序会在模拟 `Ctrl+C` 前自动等待你松开 `Alt` 等修饰键（热键在按下瞬间触发，此时 Alt 通常还没松开，
  若立即模拟复制会变成 `Ctrl+Alt+C` 而被目标应用忽略），因此**按住 Alt 稍慢松开也没问题**。
- 取词为空时小窗会以手动输入模式打开并提示原因，不会静默失败。
- 已知不适用场景：目标应用不支持复制（部分游戏、终端）、或目标应用以管理员权限运行
  （受 UIPI 限制无法注入按键）。此时请手动输入。
- 个别应用取词异常时，用 `publish\TranslationApp.exe --verbose` 启动，
  日志会记录取词时的目标窗口 pid / 窗口类 / 标题，便于定位。

### 本地高精度 OCR（FR-030 / 需求文档 14.9）

- [x] **双引擎并存**（设置 → 高级 → 截图翻译（OCR）→「本地识别引擎」）：默认 `windows`
      （`Windows.Media.Ocr`，零依赖、快，行为与此前逐字节一致）；可选 `paddle`
      （RapidOcrNet + PP-OCRv5 mobile ONNX，中英日混训，**对斜体/花体/小字/低对比度显著更准**——
      C0 探针实测斜体相似度 99.1% vs 系统 OCR 44.6%，单次识别中位 0.49s，慢 2~4 倍）。
      paddle 是显式选择的独立引擎：不参与 windows 引擎的 zh/en auto 双跑，识别语言由模型决定，
      不可用时自动回退 windows 引擎并一次性气泡提示（绝不静默失败）
- [x] **模型内置、零下载**：det/cls/rec 三件套 + 字典共 22.5MB 作为嵌入资源打进 EXE（单文件、零外置），
      首次使用时落盘到 `%TEMP%\TranslationApp\paddle-models` 并**保留复用**（重建全流程实测 174ms）
- [x] **内存策略**：懒加载（首次 paddle 识别才建 ONNX 会话，windows 路径完全不加载 onnxruntime.dll）+
      空闲 5 分钟自动释放（下次识别重建约 0.5s）+ `OcrPaddleResident` 可选常驻（常驻内存约 +30MB）；
      ONNX 会话硬性关闭 CPU 内存 Arena（默认开启会使 4MP 推理峰值 +624MB 超硬顶，关闭后 +31.8MB，代价 ~5%）
- [x] **发布体积**：`build\publish.ps1` 体积门禁同步 90MB → 200MB（2026-09-14 用户决策，
      双口径说明见脚本注释；单文件压缩率 ≈ 65%）

已知限制：

- **截图翻译不支持跨显示器框选**（13.2.3）：遮罩只覆盖鼠标所在的单个显示器。混合 DPI
  （如主屏 150% + 副屏 100%）下单个 WPF 窗口只有一个 DPI 比例，截图像素与 DIP 无法同时对齐；
  如需识别另一块屏上的内容，请把鼠标移到该屏后再按热键。
- **钉图依赖 Windows 10 的「悬停时滚动非活动窗口」设置**（默认开启）：若该设置被关闭，
  未激活的钉图收不到滚轮消息，需先单击图片激活；钉图的 `Esc` / `空格` / `Ctrl+C` 同理，
  它们只在钉图窗口激活时生效（刻意不注册为全局热键，否则会劫持其它应用的按键）。
- **`both` 模式**下点击钉图会让翻译小窗按既有规则在 200ms 后自动隐藏（"点击窗口外即隐藏"），
  这不是缺陷；该说明同时写在设置页的「截图结果处理方式」下方。
- **斜体、花体、衬线等艺术字体是 `Windows.Media.Ocr` 的已知短板**（C-⑥）：此类内容建议在设置中
  显式固定 OCR 识别语言；「自动」档已做中英双跑择优（配置文件语言引擎与 en-US 引擎各识别一次，
  按**词框总面积覆盖率**择优——几何量对「乱码更长」免疫，面积不可得时回退字符数比较，
  并对识别文本做脚本对账，映射与文本方向冲突时交回引擎自动检测；「拉丁为主混 CJK 杂质」的
  斜体歌词形态另有脚本冲突逃生口豁免得分领先要求，见需求文档 14.3.12.8），
  但艺术字体的识别质量仍受系统能力限制——**根治请切换到 PaddleOCR 本地模型**（FR-030，见上文）。
- **PaddleOCR 引擎**（FR-030）：单次识别较慢（约 0.5s 级，10 行样本）、EXE 体积约 +32MB；
  识别语言由内置的中英日混训模型决定，不受「OCR 识别语言」设置影响；首次使用需重建会话
  （约 0.5s，默认不常驻）。模型会话文件落在 `%TEMP%\TranslationApp\paddle-models`
  （与 %TEMP% 自解包同性质，不属于外置分发文件）。
- 钉图相关的观感项（覆盖底色扩边系数、`busy` 阈值、缩放步进手感、工具条淡出时长与残留透明度）
  为**需实测确认**项：当前取需求文档给出的默认值，实测不满意时可调设置项或按文档备选方案调整。
