# TranslationApp（速译）

Windows 桌面划词 / 输入翻译工具：常驻系统托盘，全局热键呼出鼠标处翻译小窗。
技术栈：C# / WPF / .NET 10（详见 `docs/需求文档-TranslationApp-v1.0.md`）。

## 环境

- .NET SDK 10（`winget install Microsoft.DotNet.SDK.10`）
- Windows 10 1809+ / Windows 11 x64，无需管理员权限

## 运行数据位置

| 内容 | 路径 |
|---|---|
| 设置 | `%AppData%\TranslationApp\settings.json`（代理密码与各引擎 API Key 均为 DPAPI 密文） |
| 历史 / 生词本 | `%AppData%\TranslationApp\history.db`（SQLite，WAL 模式） |
| 日志 | `%AppData%\TranslationApp\logs\`（按天滚动，保留 7 天） |

开启「设置 → 更新与数据 → 便携模式」后，上述数据改写到 EXE 同目录的 `data\` 下；也可在 EXE
同目录手动放置 `portable.flag`。备份包只包含 `settings.json` 与一致性 `history.db` 快照，恢复前会校验清单与 SHA-256。

### 让 Google 引擎可用（需要代理，且只开代理还不够）

默认引擎是 Bing（国内可直连）。若要用 Google：

1. **设置 → 高级 配置代理**：填代理地址与端口（Clash 常见 `127.0.0.1:7897`），协议可选
   **HTTP 或 SOCKS5**；作用范围保持「仅国外引擎」，这样 Bing 仍走直连不绕路。
2. **Google 的 `client=gtx` 参数会被限流**：实测同一出口 IP 上 `client=gtx` 稳定返回 HTTP 429，
   而 `client=dict-chrome-ex` 正常返回 200。程序已内置**多 client 依次尝试**
   （`dict-chrome-ex` → `gtx`），并把 429/403 归类为「配额用尽」而非笼统的「引擎异常」。

配置后用设置页的「测试代理连通性」验证——它直接探测 Google 翻译端点，按 200 / 429 / 403
给出可操作提示。**代理未开启时 Google 会翻译失败，此时请把引擎切回 Bing**
（设置 → 翻译 → 当前引擎），Bing 不需要代理。

实测（代理 `127.0.0.1:7897`、引擎 Google）：连续三次翻译成功，单次 115~145ms。

### 官方引擎的 Key 与网络可达性
- 四家官方引擎（腾讯云 TMT / 百度 / Azure Translator / DeepL）的密钥在**设置 → 引擎**页填入，
  经 Windows DPAPI（CurrentUser）加密后写入 `settings.json`（`*Encrypted` 字段，配置文件中无明文）；
  非密钥标识（SecretId / APPID / Region）按文档明文存储，便于排障。
- 每张卡片有「测试连接」（发一次 `hello` 的真实翻译请求，约消耗 5 个字符额度）：
  成功显示译文与耗时，失败按「Key 无效 / 额度用尽 / 网络不可达 / 引擎异常」分类给文案。
- **端点可达性实测（2026-09-13，本机直连、无代理、无 Key）**：

  | 端点 | 结果 | 结论 |
  |---|---|---|
  | `api.cognitive.microsofttranslator.com` | HTTP 401（`error.code` 401001） | 可达 |
  | `api-free.deepl.com` | HTTP 403（Missing Authorization header） | 可达 |
  | `api.deepl.com` | HTTP 403 | 可达 |

  即当前网络**无需代理**即可直连 Azure 与 DeepL。若在其它网络下不可达，设置页会给出
  「端点 xxx 当前不可达」提示；此时请到**设置 → 高级 → 网络代理**把作用范围设为
  **「仅国外引擎（Google / Azure / DeepL / AI）」**并填入代理（Azure / DeepL 归入该作用域）。
  重跑实测：`powershell -ExecutionPolicy Bypass -File build\probe-engines.ps1`。
- Azure / DeepL 在**没有 Key 时也能探测**（401/403 即视为可达），因此设置页打开后会后台探测一次，
  不可达时在对应卡片显示黄色提示条。

## 使用方式

| 操作 | 说明 |
|---|---|
| `Alt+D` | 在鼠标处呼出翻译小窗（输入翻译）；再按一次或 Esc 收起 |
| `Alt+S` | 划词翻译：自动取当前选中文本并翻译（阶段 2 实现，见「当前状态」） |
| `Alt+R` | 翻译并原位替换当前选区（默认关闭，可在热键页启用） |
| `Alt+O` | 截图翻译：框选后默认**把选区图片钉在屏幕上原位显示译文**（阶段 5，见下） |
| `Ctrl+Enter` | 小窗内交换源/目标语言 |
| 托盘双击 | 打开设置 |
| 托盘右键 | 输入翻译 / 划词翻译 / 截图翻译 / 设置 / 隐私模式 / 退出（存在钉图时多一项「关闭所有钉图」） |
| 复制文本 | 开启「剪贴板监听」后自动弹出翻译（设置 → 高级，默认关闭） |
| 译文行按钮 | 收藏到生词本 / 朗读译文 / 复制译文；输入框右上角可朗读原文 |

小窗失去焦点会自动隐藏（200ms 延时），隐藏时会把键盘焦点交还给你原来的应用；
点「图钉」可按需求固定常显。热键、目标语言、引擎均可在设置中修改，改动即时生效。

### 首次使用引导

首次启动会在 1.2 秒后打开三步引导：选择引擎 → 录入并确认真实核心热键 → 运行能力自检。热键框与设置页共用同一录制控件，录入后即时显示可用、重复或被系统占用；每项都可单独恢复默认。自检覆盖引擎、热键注册和 Windows OCR 语言包；失败时可以重新检查、稍后测试，或直接进入 **设置 → 诊断** 查看修复入口。引导只显示一次，之后可从 **设置 → 通用 → 再看一次** 重新打开。

### 翻译并原位替换

在任意应用中选中文字后按 `Alt+R`，程序会复用当前引擎、术语表和 TM 完成翻译，并把译文直接覆盖原选区。默认关闭；启用入口在 **设置 → 热键**。替换过程不显示确认窗或结果窗，避免焦点和选区被弹窗破坏。

替换采用一次粘贴操作，直接进入目标应用自己的 `Ctrl+Z` 撤销栈；程序会保存并恢复原剪贴板。若目标应用不支持复制、粘贴或撤销，请改用普通划词翻译后手动粘贴。隐私模式下不读取 TM，也不写翻译历史；是否写历史由 **设置 → 热键 → 替换后写入翻译历史** 控制。

### Doctor 诊断中心

**设置 → 诊断** 可集中检查全局热键占用、Windows/Paddle OCR、代理连通性、SQLite 快速完整性、数据目录可写性、更新清单验签与 EXE 替换权限。代理和更新通道检查会在点击“开始诊断”后联网，其余检查只读本地状态或创建短暂探针文件。结果可复制或导出为脱敏 TXT 报告，不包含 API Key、原文、译文或 Token。

热键、OCR、代理和更新问题会给出“打开对应设置”的入口；数据库或目录问题可直接打开数据目录，未知警告可重新诊断。

### 钉图窗口（阶段 5，FR-027）

框选后图片会**钉在屏幕上原选区的位置**（`zoom = 1.0` 时逐像素还原），原文字位置上直接显示译文。
钉图四周有**扩散阴影外框**（圆角卡片），工具条在**截图下方的常驻条带**里（不遮挡图片文字）。
钉图窗口是常驻的独立窗口（不进 Alt+Tab、初始不激活、不打断你的编辑），**它自己永不自动隐藏**，
只能由你关闭。快捷键只在钉图窗口处于激活状态时生效（先单击图片即可）：

| 操作 | 说明 |
|---|---|
| 拖动图片 | 移动钉图（不写回任何设置） |
| 滚轮 | 以鼠标位置为锚点等比缩放（默认每格 ×1.1，可在设置里改） |
| `Shift+滚轮` | 精细缩放（按缩放步进的 20% 折算） |
| `Ctrl+滚轮` | 单张钉图的透明度（步进 0.1，范围 30%~100%，不写回设置） |
| 单击图片 / `空格` / `T` / 双击 | 在原文与译文之间切换 |
| `Ctrl+C` / `Ctrl+0` / `Ctrl+=` / `Ctrl+-` | 复制译文 / 回到 100% / 放大 / 缩小 |
| `Ctrl+R` | 重新翻译（翻译失败时可用） |
| `Ctrl+F` | 强制翻译（「识别语言与目标语言相同」被跳过时，工具条出现「翻译」按钮，把源语言置回自动检测重新翻译） |
| `Ctrl+Enter` | 把识别文本带回翻译小窗（可编辑、可再翻译、可入库） |
| `Esc` | 关闭这张钉图；托盘「关闭所有钉图」一次清空 |
| 右键菜单 | 放大 / 缩小 / 原始大小 / 切换原文译文 / 复制译文 / 在小窗中打开 / 重试翻译 / 强制翻译 / 恢复不透明 / 关闭（不可用的项会禁用并写明原因） |

钉图条数上限 5 张、单张 4 MP（超出自动等比缩小并提示）、总量 12 MP（超出拒绝并提示）；
达到上限**不会**静默关闭你已有的钉图。

### 划词翻译（Alt+S）使用要点

- 用法：先在任意应用中**选中文字**，再按 `Alt+S`。
- 程序会在模拟 `Ctrl+C` 前自动等待你松开 `Alt` 等修饰键（热键在按下瞬间触发，此时 Alt 通常还没松开，
  若立即模拟复制会变成 `Ctrl+Alt+C` 而被目标应用忽略），因此**按住 Alt 稍慢松开也没问题**。
- 取词为空时小窗会以手动输入模式打开并提示原因，不会静默失败。
- 已知不适用场景：目标应用不支持复制（部分游戏、终端）、或目标应用以管理员权限运行
  （受 UIPI 限制无法注入按键）。此时请手动输入。
- 个别应用取词异常时，用 `publish\TranslationApp.exe --verbose` 启动，
  日志会记录取词时的目标窗口 pid / 窗口类 / 标题，便于定位。

      批 4 已知边界：**词典仅支持 MDX v3-SQLite**，判据是「资源块页头 + `Term` 表」，不做全文页头扫描
      （那会把任意位置撞上 SQLite 魔数谎称支持）；v1/v2、缺表、非 mdx 文件都在导入时给出中文原因并回滚，
      列表里显示为「不可用」而非静默消失。段落对齐不做逐句（段 = 空行分隔），对齐失败静默回整块。

### P0 批 5（FR-050 ~ FR-055，2026-09-21，spec `docs/superpowers/specs/2026-09-20-p0-batch5-prompt-style-review-shadow-design.md`）

- [x] **FR-050 AI 语境化翻译**（默认开）：可选接口 `IPromptDirectiveTranslator`（`ITranslator` 零改动，
      六家引擎不受影响），语境取「同目标语言 30 分钟内、且与当前输入不同」的最近一条原文写进系统提示
      （明确标注"不要翻译它、不要输出它"，截尾 600 字符）。**不多送一个字**：那段文本本来就在同一引擎的
      历史出网请求里；隐私模式/自定义 Prompt 无 `{context}` 占位符时一律不追加。日志只记字符数
- [x] **FR-051 一键换说法**：小窗译文下方「更口语 / 更正式 / 更简短」三颗轻按钮（仅 AI 引擎显示，
      官方引擎没有这条通道就不装支持），点已激活的那颗 = 取消；重请求**不写历史**（同句多译会污染 TM 候选池）、
      不自动朗读；`TranslationStyle` 持久化，本地 HTTP API 也沿用同一风格（脚本与手动不该两种口吻）
- [x] **FR-052 生词本每日 5 词**（默认关）：`DailyReviewSelector` 纯轮转（天数×5 取模环形取），
      同一天稳定、跨天自动往后挪；进度落在设置 JSON（`DailyReviewDate`/`DailyReviewIndex`），
      **不加表不加列**；小窗里一行复习卡（`今日复习 2/5 · 词 → 释义` + 「下一个」「今天到这」）。
      刻意不做熟悉度/遗忘曲线——那是 B4 复习闭环的正题，这里只做最轻的提醒
- [x] **FR-053 影子跟读**（默认关）：`SentenceSplitter` 按句末标点/换行切句、引号跟着前句、
      碎句并入、200 字符强切；译文区「跟读」→ 逐句竖排 + 当前句左侧强调条，
      `TtsService.SpeakAndWaitAsync` 用轮询 `State`（60ms）而非 `SpeakCompleted` 事件
      （取消时事件会晚到，会把下一句误判成"已念完"），句间停顿可配 200~3000ms；
      只用系统语音 SAPI，不联网、不外发文本；`Esc`/关窗/换会话即停
- [x] **FR-054「写作」场景档案**：`ProfileOverrides` 键集合 8→9（新增 `Style`，三处同步），
      内置三档「阅读 / 隐私 / 写作」，写作档钉 `llm + formal + 关阅读清洗`，
      **不钉目标语言**（钉了会让切档案顺手改用户的语言）；设置页档案按钮改为按 `AllProfiles()` 生成
      （原先三颗按钮硬编码，加一档就漏一档）
- [x] **FR-055 词典来源标注**：`DictionaryQueryHit.SourceName` 带回命中的词典名，小窗词典卡标题变
      「词典 · 长语林」——多词典「按列表顺序取首个命中」必须可解释。词条并集/交叉释义拼接**不做**
      （mdx 的 Definition 常是整页 HTML，拼接后可读性反而下降，且"哪本给的"变得不可解释），
      此即 A2-1 的评估结论

批 5 已知边界：跟读进行中「再点一次停止」这条路径由 `Esc → 关窗 → 取消` 验证（重新呼出后列表已清空、
回到整块视图），harness 的第二次像素点击未送达，详见 spec §11；语境只在 AI 引擎生效，
且自定义 Prompt 需用户自己写 `{context}` 占位符。

### P0 批 6（FR-056 ~ FR-059，2026-09-21，spec `docs/superpowers/specs/2026-09-21-p0-batch6-ai-dict-history-groups-app-rules-design.md`）

- [x] **FR-056 AI 词典兜底**（v2 A2-1 轻量前置版，默认关）：本地 mdx 没命中时，向 AI 引擎再发一次
      "只回 JSON"的请求，出「词头 + 音标 + 简明释义」，显示在同一张词典卡上（来源标「AI 词典」）。
      `AiDictionaryParser` 按容错提取写（剥 ``` 围栏与前后散文、自己扫字符串修尾逗号、容忍
      `wordhead|term|词头` 等别名与对象型释义），**解析不出可用结构就返回 null**——宁可不出卡片，
      也绝不把半截 JSON 甩给用户。默认关是因为它每次查词都花用户的 API 额度；走 `Unwrap` 后的裸引擎
      （不计入引擎看板、不被术语表改写），8 秒拿不到就放弃
- [x] **FR-057 历史按会话分组**（v2 B4-2，默认开）：`HistoryGrouper` 纯函数按"相邻 ≤30 分钟"归组，
      组标题给「时间范围 · N 条 · 首条摘要」，可折叠；**只改视图层**——仓储/导出/删除仍按单条 Id，
      不加表不加列；搜索时自动回平铺（跨组结果再切组会把最该看的那条藏起来）
- [x] **FR-058 按应用记忆语言对**（v2 B3-2，默认关）：`AppLanguageRules` 纯逻辑（进程名归一化、
      先匹配者胜、学习置顶覆盖同名、上限 20 条）；命中时**只改本次会话**的语言——直接写 backing field
      绕开 setter，避免"切个浏览器就把默认语言偷偷改了"；用户在某应用里手动改语言即被记住。
      进程名取自小窗的前一个前台窗口，只在本机比较与存 settings.json，**不读窗口标题、不写日志、不出网**
- [x] **FR-059 首次运行三步引导**：独立一次性窗口，依次选择引擎、录入真实核心热键并运行能力自检；
      自检失败可重新检查、稍后测试或跳转 Doctor；标记在弹之前就落盘（直接结束进程也不会下次再弹），
      设置页「通用」留了「再看一次」

批 6 已知边界：AI 词典不做例句/图片词条，模型给什么就显示什么（超 6 条截断）；历史分组不做项目命名与标签；
按应用记忆不做窗口标题级匹配（标题会变，也更贴近"读取用户在看什么"）。

已知限制：

- **截图翻译不支持跨显示器框选**（13.2.3）：遮罩只覆盖鼠标所在的单个显示器。混合 DPI
  （如主屏 150% + 副屏 100%）下单个 WPF 窗口只有一个 DPI 比例，截图像素与 DIP 无法同时对齐；
  如需识别另一块屏上的内容，请把鼠标移到该屏后再按热键。
- **钉图依赖 Windows 10 的「悬停时滚动非活动窗口」设置**（默认开启）：若该设置被关闭，
  未激活的钉图收不到滚轮消息，需先单击图片激活；钉图的 `Esc` / `空格` / `Ctrl+C` 同理，
  它们只在钉图窗口激活时生效（刻意不注册为全局热键，否则会劫持其它应用的按键）。
- **`both` 模式**下点击钉图会让翻译小窗按既有规则在 200ms 后自动隐藏（"点击窗口外即隐藏"），
  这不是缺陷；该说明同时写在设置页的「截图结果处理方式」下方。
- **斜体、花体、衬线等艺术字体是 `Windows.Media.Ocr` 的已知短板**（C-⑥）：此类内容建议在设置中
  显式固定 OCR 识别语言；「自动」档已做中英双跑择优（配置文件语言引擎与 en-US 引擎各识别一次，
  按**词框总面积覆盖率**择优——几何量对「乱码更长」免疫，面积不可得时回退字符数比较，
  并对识别文本做脚本对账，映射与文本方向冲突时交回引擎自动检测；「拉丁为主混 CJK 杂质」的
  斜体歌词形态另有脚本冲突逃生口豁免得分领先要求，见需求文档 14.3.12.8），
  但艺术字体的识别质量仍受系统能力限制——**根治请切换到 PaddleOCR 本地模型**（FR-030，见上文）。
- **PaddleOCR 引擎**（FR-030）：单次识别较慢（约 0.5s 级，10 行样本）、EXE 体积约 +32MB；
  识别语言由内置的中英日混训模型决定，不受「OCR 识别语言」设置影响；首次使用需重建会话
  （约 0.5s，默认不常驻）。模型会话文件落在 `%TEMP%\TranslationApp\paddle-models`
  （与 %TEMP% 自解包同性质，不属于外置分发文件）。
- 钉图相关的观感项（覆盖底色扩边系数、`busy` 阈值、缩放步进手感、工具条淡出时长与残留透明度）
  为**需实测确认**项：当前取需求文档给出的默认值，实测不满意时可调设置项或按文档备选方案调整。
